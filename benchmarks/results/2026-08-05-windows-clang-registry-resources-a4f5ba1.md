# Registry layer 资源策略基准

## 环境

- 提交：`a4f5ba1`
- preset：`windows-clang-benchmark`
- 编译器：Clang 22.1.8
- CPU：Intel Core i5-8600K，6 核 6 线程
- 参数：`caors_benchmarks 100000`
- 方法：同一 Release 可执行文件连续运行 3 次；每种策略注册 8 个带属性、方法和序列化字段的类型，
  查询阶段执行 800000 次类型查询。

## 耗时

| 操作 | system | monotonic | size class pool |
| --- | ---: | ---: | ---: |
| 注册，第 1/2/3 轮（μs） | 140.3 / 106.4 / 98.0 | 61.2 / 58.9 / 60.2 | 54.5 / 50.9 / 51.8 |
| 注册中位数（μs） | 106.4 | 60.2 | 51.8 |
| 查询，第 1/2/3 轮（ms） | 88.18 / 87.09 / 86.14 | 87.05 / 86.22 / 85.36 | 98.12 / 87.49 / 88.14 |
| 查询中位数（ms） | 87.09 | 86.22 | 88.14 |
| 卸载，第 1/2/3 轮（μs） | 18.8 / 20.4 / 20.8 | 12.4 / 10.8 / 10.8 | 13.0 / 12.5 / 11.5 |
| 卸载中位数（μs） | 20.4 | 10.8 | 12.5 |

## 内存

| 策略 | 上游分配次数 | live bytes | 卸载后保留 | 显式释放后 |
| --- | ---: | ---: | ---: | ---: |
| system | 107 | 14520 | 0 | 0 |
| monotonic | 6 | 28768 | 28768 | 0 |
| size class pool | 18 | 31960 | 31960 | 0 |

monotonic 和 pool 会将已释放块保留到资源整体 reset/release，因此 layer 卸载后仍有上游占用属于预期行为。
三种策略完成各自最终释放后，上游 `bytes_in_use` 均为 0。

## 结论

- 查询中位数最大差异约 2.2%，说明已发布 registry 的查询热路径基本不依赖 layer 分配策略。
- monotonic 和 pool 减少了注册期间的上游分配，并缩短这个小样本中的注册、卸载时间；代价是 live
  内存分别约为 system 的 2.0 倍和 2.2 倍。
- 当前 workload 只有 8 个类型，注册和卸载每轮仅执行一次，而且策略执行顺序固定；该数据不足以证明
  在真实插件规模和生命周期下仍有净收益。
- 继续以 system resource 作为 registry 默认策略。保留显式资源注入能力，等真实插件 workload 能证明
  注册延迟或分配竞争是瓶颈后，再评估按 layer 使用 monotonic；当前不默认接入 pool。
