# 串行分块聚合与逐块消费

## 状态与当前能力

已完成，C51-09，目标范围见 [v0.5.0](../versions/v0.5.0.md)。用户已确认采用新增 helper、串行同步消费及背压方案；具体签名由公共头维护。
当前 read_all_bounded 把打开时文件长度作为一次 request_read 长度；有总结果上限但不自动分块。
request_read 已具备精确范围校验、短段累积和通知协议，继续复用；不新增路由或文件打开体系。
当前契约见[IO 参考](../reference/io.md)。

## 候选方案

| 方案 | 收益 | 代价 |
| --- | --- | --- |
| 调用方自行循环 request_read | 无新 API | 宿主重复实现取消、投递和 inline 重入状态机 |
| read_all_bounded 内部自动分块 | 老调用直接受益 | 改变旧操作次数、分配及失败时序 |
| 新增聚合与逐块消费 helper | 保留旧行为、意图清楚；推荐 | 增加两个入口及共享内部推进状态 |

采用 read_all_chunked / consume_chunks，保留 read_all_bounded 现状。
前者返回完整 byte_buffer；后者返回最终消费状态，不累计整文件数据。
不把聚合结果内存宣称为 O(块大小)。

## 建议契约

- 两类操作均明确总处理字节预算与块大小上限；实际单块为剩余量、配置上限和后端 max_read_size 的最小值。
- 拒绝零块大小；总量、offset 加法、size_t/PTRDIFF_MAX、聚合结果可表示性在分配前验证。
  逐块消费允许总处理量大于 size_t，但每块必须可表示；总处理预算不等于驻留缓冲预算。
- 首版最多一个在途块，按 offset 顺序交付；打开时长度固定，增长不扩展，提前 EOF 保留 short_read。
- 聚合预留完整结果并逐块填充；应计算完整结果加临时块的峰值，预算/分配失败必须在文档和测试中可见。
- 推荐首版消费者同步返回成功/错误，仅在指定 executor 的调用期间借用 const span；不得保存视图。
  回调返回后才能申请下一块，自然形成背压。消费异常转换为明确失败，不能从回调抛出后继续读取。
- 异步确认/拥有式块转移是另一候选，首版建议延期：需新增等待确认、丢弃和取消协议。
  恢复条件为真实异步消费需求及协议评审；同步消费者已经满足本版逐块消费范围，不阻塞验收。
- 消费/最终通知经指定 executor；拒绝/丢弃均有可查询终态，无 I/O 线程补调。
- 进度按“已消费完成字节”统计，聚合按“已并入结果字节”统计，不按排队量统计。
- 取消后不启动新块，不等待正在运行的同步消费者被抢占；回调结束后检查停止信号并完成实际清理。
  已产生的消费副作用不回滚；需要事务时由调用方暂存。
- helper 持有 shared_ptr<async_file> 保活，不取得独占文件所有权，不隐式关闭调用者共享文件。
- 使用迭代推进/重入闸门；inline executor、即时完成和大量单字节块不得造成递归栈持续增长。
