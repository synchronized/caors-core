# 外部 executor 适配计划

## 状态与范围

状态：实施中，对应 C51-06。版本与依赖见 [v0.2.0](../versions/v0.2.0.md)。
现有 `tasks::executor` 主要由 CAORS context/thread_pool 构造；新增宿主投递适配，
保持 Asio 私有，不要求引入 libuv 依赖或新建线程池。

## 设计与实施

- [ ] 设计受控外部投递入口，复用 `tasks::task` 与现有错误模型；确定适配状态所有者及 allocator。
  非拥有的宿主上下文也必须通过关闭/保活协议防止回调悬空。
- [ ] 明确提交前、接受成功后、拒绝后的任务所有权及恰好一次销毁责任；
  不能让宿主接受后静默丢弃任务而使关联请求永久 pending。
- [ ] 定义关闭过程及接受/关闭竞争：停止新提交、完成或取消已接受工作、排空回调，然后释放上下文。
  adapter 句柄晚于宿主销毁时返回明确错误，不访问旧用户指针。
- [ ] 规定同步 inline 接受的重入语义与是否允许，禁止持有内部锁调用宿主回调。
  任务异常、拒绝投递和丢弃路径必须映射到现有请求终态。
- [ ] 用模拟宿主线程池和所属线程完成队列接入资源加载；后台任务与 cache commit 分别投递，
  不放宽资源 cache 的所属线程约束。复用模块寿命及独立订阅取消规则。
- [ ] 补公共头注释、tasks/resources 参考及可运行示例；不泄漏 Asio 类型，不新增平行 request 系统。

## 验收

覆盖正常接受、拒绝、关闭、已接受任务丢弃、inline 重入、提交/关闭竞争和 adapter 句柄晚销毁。
验证 task 销毁恰好一次、请求都有终态、上下文释放后无回调；使用线程 ID 断言 cache commit 发生在所属线程。
集成 A/B 共享加载、A 取消而 B 成功，以及全部取消与宿主关闭场景；模块卸载遵守统一寿命协议。
Windows/Linux 和 sanitizer 验证通过，记录 API 契约、线程模型及实际执行证据。

## 未决与阻塞

外部上下文的关闭握手、接受后丢弃通知和所有权转移为设计门槛；仅有裸 post 回调不足以通过验收。
P2 表示最后一批，不自动延期；若宿主适配需求无法定稿，需按版本页规则显式调整范围。
宿主具体 libuv 集成在下游完成，CAORS 自有模拟队列覆盖协议；当前无新增实现或验收证据。
