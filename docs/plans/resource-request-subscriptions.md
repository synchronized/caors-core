# 共享资源请求的独立订阅取消计划

## 状态与范围

状态：实施中，对应 C51-05。版本归属见 [v0.2.0](../versions/v0.2.0.md)，寿命约束复用
[资源模块寿命计划](resource-module-lifetime.md)。现有请求复用共享状态，`cancel()` 取消该共享状态，
这是当前契约；本计划新增消费者隔离，不把现有行为直接记为缺陷。

## 设计与实施

- [ ] 分离底层加载 operation 和独立订阅状态；同类型同 GUID 复用一次加载，不复用消费者终态。
  普通句柄复制共享同一订阅，新的独立请求产生新订阅；具体入口与命名在 API 评审中确定。
- [ ] 单订阅取消后只向该订阅交付取消，其他订阅仍可成功；定义取消与成功竞争的唯一终态线性化点。
  全局取消如保留须有明确入口和权限，不能与取消个人等待混用。
- [ ] 全部订阅取消后，提出底层合作取消并阻止无需求的 cache 提交；不强制中断运行中的 loader。
  定义缓存提交与订阅取消的先后判定，以及新订阅到达已放弃 operation 时重建/复用策略。
- [ ] 梳理 load/preload、依赖图、缓存命中、失败、coroutine waiter、进度与 assets 调用链，
  防止父订阅退出错误取消其他消费者仍需要的依赖。
- [ ] 规定请求析构是否等于取消，等待者 detach 的含义，以及成功、失败、取消恰好一次交付的 executor。
  executor 拒绝或关闭也必须有终态，不允许永久 pending。
- [ ] 记录公开 API 迁移：若改变旧 `cancel()` 含义，提供明确替代入口、示例和 CHANGELOG，
  发布前更新当前参考，实施前不把计划语义写成当前行为。

## 验收

A/B 同资源只加载一次；A 取消后不接收成功应用结果，B 成功；普通复制与独立订阅语义分别测试。
覆盖全部取消、取消后新订阅、加载失败、缓存命中、提交前取消、完成/取消竞争、依赖 preload 和关闭。
用屏障控制竞争窗口，不依赖 sleep 碰概率；检查 loader 次数、cache 提交次数、终态次数和释放计数。
Windows/Linux、ASan/UBSan 与重复竞争测试无永久 pending、重复完成、泄漏和错误缓存提交。

## 未决与阻塞

全局取消权限、订阅析构行为、取消/提交竞争规则与兼容迁移必须先定稿，均阻塞本计划验收。
具体错误码、签名与状态机需复用现有请求协议，不另造一套与 tasks 无法互操作的终态模型。
当前无新增独立订阅验收证据。

## 本轮推进

实现批次 `c3b262e` 已提交，仍需完成本计划全部验收；过程与结果统一记入
[版本验收记录](../records/2026-10-19-v0.2.0-host-integration.md)。本页原复选项在逐项核实后收口，
不能仅凭实现提交标记全部通过。

本轮保留现有请求类型，各次加载调用返回独立订阅，普通复制共享订阅，`cancel_shared()` 表达全局取消。
析构句柄不自动取消；全部订阅取消可放弃尚未开始的缓存提交，提交进入临界点后不回滚。
