# 资源、allocator 与模块寿命计划

## 状态与范围

状态：讨论中，对应 C51-02，P0；版本与依赖见 [v0.2.0](../versions/v0.2.0.md)。
现有 `resources::handle` 控制块保留销毁回调与 allocator 指针，未自动拥有模块 lease。
registry layer 的保活不等于通用资源安全；当前不能宣称任意资源可在模块卸载后释放。

## 设计与实施

- [ ] 列出依赖链：资源析构代码、强/弱控制块、allocator 对象及实现、loader、后台任务、完成回调和擦除操作。
  区分对象释放时点与最后弱引用释放时点。
- [ ] 先评审复用 `plugin_library_lease` 的可选保活与宿主显式 pin 两种方案，选择一个最小主路径。
  不强制普通静态资源依赖插件模块；公开签名在寿命规则确定后设计。
- [ ] 对 allocator 位于模块内的情形，保活覆盖最后弱引用及控制块内存释放完成；
  销毁 lease 自身所需的代码和 allocator 也必须有效，不能先卸载再执行最后一次 deallocate。
- [ ] 将异步任务与回调计入卸载协议：停止接收、发出取消、等待/排空或明确拒绝卸载。
  “请求取消”不等于任务已经停止；completion executor 尚有任务时不能提前关闭模块。
- [ ] 设计资源创建、加载失败、取消、异常和关闭路径的 RAII 回收；防止 manager、资源与 lease 互持形成循环。
- [ ] 更新 resources 参考与插件指南，并补跨动态库的真实资源、allocator 和回调测试。

## 验收

仍有强引用时请求卸载不得执行失效代码；只剩弱引用时控制块最终释放安全；
最后一个弱引用销毁完成后模块可按协议卸载。销毁、deallocate 和模块关闭顺序须可观测。
创建/加载失败、取消及任务投递失败无 lease 泄漏；后台工作和回调未结束时卸载延迟或返回明确错误。
卸载后无悬空回调，反复加载/释放/卸载无永久 pin 或重复释放。
Windows/Linux 共享库用例配合 ASan/UBSan 与确定性同步压力测试；实际结果入 Record。

## 未决与阻塞

保活所有者、最终弱引用释放时的卸载顺序、循环规避和卸载诊断均需设计评审，未解决则阻塞本版。
宿主外部对象不遵守协议的任意强制卸载不保证安全；不将文档约束冒充自动保护已实现。
