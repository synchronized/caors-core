# VFS 文件访问接口收敛计划

## 状态与范围

访问主线与独立路由已通过平台验收，职责收敛实施中。用户已确认路由、调用方访问与后端协议分离，以及统一 open 命名。
承接[资源 API 收敛](io-assets-api-consolidation.md)，不改已公开版本标签。

只读访问、可写句柄、整体操作与独立路由已有验收证据；当前任务是减少重复职责和兼容转换。
2026-10-23 按用户确认修订目标：不再以删除 file_system 类作为验收条件。
同步工具和保存可继续复用现有实现，设计依据见[IO 职责与实现复用](../concepts/io-boundaries.md)。

## 已确认需求

- vfs 仅负责挂载与快照，不继承文件后端；统一普通路径与 URI 的配置入口，但保留原匹配语义。
- 挂载拥有 backend，后端构造绑定 worker 或宿主 loop；普通访问不逐次传 executor。
- io_context 初始化配置 completion 与借用分配器；read 整体组合打开、限量读取和关闭。
- 文件入口统一 open(path, options, callback)，不命名 open_read/open_write。
- open 默认只读且只打开已有文件。第一批只暴露可实现的只读选项；写入/读写、创建/截断随实现开放。
- file 提供基于 offset 的读取和显式 close，句柄拥有实际文件；析构非阻塞清理兜底。
- 普通 API 直接返回单层 request<T>，参数/发起/执行/投递失败统一可查询；回调经配置 completion，拒绝/丢弃不保证回调执行。
- 取消为协作行为，不能等同于底层清理完成；后端、模块凭据和 allocator 须覆盖真实操作。
- 每次路径操作在发起时固定路由，显式 snapshot 可用于批次一致性；快照不冻结磁盘内容。
- 资源读取桥接到同一 IO 编排，不复制第二套打开/读取/关闭状态机。

## 实施顺序

1. 建立 request/file/io_context 与独立 backend；只读 open/read/close、内存与 worker 文件后端。
2. vfs 挂载、拥有式快照和旧路由适配；原匹配及嵌套快照保持语义。
3. 资源 byte_reader 复用 IO 整体读取，迁移示例、安装与浏览器消费。
4. 写入、目录与属性已有独立实现和验收；继续核对配置、保存和来源的真实调用点。
5. 复用本地/内存实现，减少重复路由及来源转换；同步工具和异步接入保持明确边界。
6. 只删除已无独立职责、消费已迁移的接口；按风险完成原生、sanitizer、真实 Web、安装及必要压力验收。

## 当前进展

## 验收

首批至少覆盖原生/内存读取、文件范围读取、关闭、预算、取消、发起拒绝、完成队列丢弃、
内联回调、路由切换后旧请求/批次稳定、后端寿命和插件凭据。
写入、枚举及元数据有独立替代证据前不能移除旧能力；不得用同步等待模拟异步。
执行证据进入 records，当前行为进入 reference/io.md，计划不维护重复 API 全量声明。

## 兼容退出的剩余范围

旧配置工厂整体退出和兼容层删除尚未完成：同步 saver 和工具流仍共享 file_system，直接删除会丢失现有保存能力。
新普通入口已隔离这些类型，但这不等于所有旧能力完成异步替代。
兼容删除须在配置消费迁移、保存替代与上游升级验证后执行；不得通过让旧配置运行时返回 unsupported 代替迁移。
现有兼容消费仍需维护；保留同步能力不阻塞已独立验收的新文件访问批次，也不要求为删除类而重写保存。

## 首批旧入口删除

已删除五个重复公共请求函数，安装消费、资源加载测试及普通分块示例迁到新入口。
内部编排头移入 src，保留对真实生命周期与模块卸载的内部回归。
同步保存依赖、旧配置工厂与尚未完整替代的高级逐块消费暂保留，范围不记为全部删除。
本批原生、Web、安装、插件专项及 Linux/Windows/Web 平台验收均通过，见[删除记录](../records/2026-10-22-io-legacy-api-removal.md)。

## 资源来源迁移（待验收）

新链路为 provider.snapshot → source.capture → backend_location → file_byte_reader。
每个 source 在单次批次只捕获一次，GUID 位置在捕获阶段解析并保存；resolve 不再重新走旧路由。
vfs_source 的 snapshot_bridge/backend_bridge 已删除，新挂载后端直接进入资源快照。
旧 file_source 在内部保留必要的单向后端适配，继续复用同步实现和旧嵌套路由冻结，不影响保存及工具消费。

加载层的 file_read_mode 和 JSON 工厂读取模式参数已删除；原生文件使用构造绑定 worker 的 backend。
内部整体读取仅保留 backend_location 入口，取消、预算与关闭仍复用同一状态机。
新增精确后端身份、跨 GUID 来源一致性、宿主凭据保活、一次解析及错误隔离回归。
本机原生、安装、插件及真实 Web 已通过，平台 CI 待验收，见[资源后端快照记录](../records/2026-10-23-resource-backend-snapshots.md)。

## 收口条件

- 普通用户无需了解同步后端、旧路由和兼容扩展即可访问文件；现有公开入口保持明确。
- 本地文件、内存存储、属性及目录算法保持唯一实现，异步适配复用同步能力或直接使用宿主原生 IO。
- 每项删除都能对应到失去独立职责的入口及已迁移的调用点，不以类型数量为唯一指标。
- 配置、保存、工具、资源读取和插件生命周期保留真实消费测试；不以 unsupported 占位替代现有功能。
- 新旧路由并存的剩余消费范围明确，未完成项不得描述成已收敛；受影响平台验收通过。
