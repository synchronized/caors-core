# 版本准备与发布自动化计划

## 状态与范围

状态：待实施，尚未排期。当前只完成[人工流程](../guides/release.md)、
[CI 策略](../guides/ci.md)、清单与模板，本计划不代表脚本或 Release workflow 已经可用。
不在本次文档整理中创建标签、推送版本或发布制品。

## 已有基础

唯一版本模块、生成头与运行时版本查询、安装导出、四类独立 consumer、Linux/Stress workflow、
本地 MSVC 包装脚本。版本准备只修改 [caors_version.cmake](../../cmake/caors_version.cmake)；根 CMake 读取该模块，不维护第二份版本值。

## 实施顺序

1. 实现只修改版本元数据的准备工具：默认展示 diff，限定文件集合；不自动推送、建 tag 或发布。
2. 实现独立只读门禁：版本格式与唯一性、固定 main SHA、版本文档、Plan 状态、非空 CHANGELOG、
   候选 Record 和阻塞项；失败信息应指出具体文件与原因。
3. 补 Windows 验证与发布构建环境，按声明的编译器/CRT/链接模式执行干净构建、安装与 consumer。
4. 定义版本化源码/SDK 包、单一顶层目录、manifest、SHA-256 和私有依赖/安装审计。
5. 为固定 SHA 手动触发发布：先完成构建与包验证，再创建 tag/Release，不以变化中的分支名发布。
6. 重新下载公开制品复核，记录失败状态；并发防重、网络中断、已有 tag/Release 的恢复策略先设计后实现。

## 测试与验收

- 成功准备只改声明文件；脏工作树、非法版本、重复标签、状态不完整、空 Changelog、失败测试均拒绝。
- 源版本、生成版本、manifest、校验和、下载字节与固定 SHA 一致。
- 托管环境与本地配置不一致时不扩大兼容承诺，跨平台缺口可诊断。
- 门禁失败不留下新标签；发布中断先检查真实远端状态，不盲目重复创建。
- 公开版本不可变；修复采用新修订版本，不靠强推或静默覆盖制品通过检查。
- Windows/Linux 工具提供一致阶段边界，验收后才把文档中的“人工”替换为实际自动化入口。

## 非目标与未决问题

不复制 Granit 的图形后端、C11 component ABI 快照或共享库 SDK 发放策略。
首批二进制矩阵、长期签名、依赖打包、发布权限配置和首次目标版本仍待明确，不虚构已完成平台验证。
