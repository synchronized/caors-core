# 统一 VFS 与异步范围读取开发计划

状态：实施中，目标版本见 [v0.4.0](../versions/v0.4.0.md)。本计划维护已确认决策、实施任务和验收要求；

## 已确认决策

| 议题 | 决策及边界 |
| --- | --- |
| 唯一权威 | 扩展现有 file_system 的可选能力，resolver/mount 共用路由；IO 不依赖 resources，不另建异步 VFS 挂载表。 |
| 来源切换 | remount 只影响后续路由，不自动清缓存、不取消旧操作；需要新来源时显式 reload 或独立资源上下文。 |
| 加载快照 | 根资源及依赖解析共用一次加载的路由快照；固定后端与路径关系，不保证外部文件内容不可变。 |
| 所有权 | 保留同步借用挂载，增加拥有式挂载；异步路径必须持有后端及必要寿命凭据，缺失时明确拒绝。unmount 不使已持有的文件/快照悬空。 |
| 模块与 allocator | owning 指针不自动阻止 DLL 卸载；后端、模块 pin、loop 状态及 allocator 必须覆盖真实清理，宿主负责正确提供寿命。 |
| 同步适配 | 默认 unsupported，不隐式阻塞或整文件回退；显式 worker 适配器允许占用工作线程，不宣称内核非阻塞。 |
| 缓冲所有权 | 首版只提供操作拥有的结果缓冲，成功后转移给结果；取消不能提前释放真实 I/O 仍使用的内存。 |
| 请求与通知 | 启动拒绝直接返回错误且无用户通知；接受后有可查询请求句柄和完成通知。完成 executor 拒绝/丢弃后进入可查询失败，不在 I/O 线程补调用户代码。 |
| 精确范围 | uint64 offset/length 先验证边界、溢出、size_t 与后端限制；读满才成功，底层短段可累计，提前 EOF 报短读。零长度可位于 EOF，增长不扩大打开时长度。 |
| 预算 | CAORS 检查明确的单请求结果上限，read_all_bounded 同样受限；全局在途字节、请求数、排队与优先级由宿主管理，不内置全局排队器。 |
| 取消裁决 | 成功/失败/取消只有一次终态裁决；取消不撤销已经确定的成功。最后调用方句柄析构放弃结果并协作取消，不阻塞等待。 |
| 共享层次 | 资源层继续按 GUID 共享首次操作与快照；新订阅不能替换该操作来源。IO 层每次区间请求独立，取消一个不取消其他区间。 |
| 并发路由 | 修改挂载和获取快照由路由层内部同步，可用短时锁；旧快照不可变且跨线程只读。路由器析构前停止新访问，后端线程能力单独约束。 |
| 嵌套路由 | 捕获嵌套 resolver/mount 的稳定状态，不在读取中重新查询实时路由；检测循环。自定义路由后端无法提供稳定快照时明确拒绝。 |
| 来源标记 | 进程内挂载实例身份，新挂载产生新身份，透明转发不凭空换身份；不作为持久 GUID 或内容摘要。 |
| 随机读取 | 每次按 offset 独立定位，允许多个请求在途；后端可并行，seek/read 显式适配器须加锁串行且不能宣称并行。 |
| 文件关闭 | 显式异步关闭加析构兜底，开始关闭后拒绝新读，已接受请求清理后真实关闭；重复关闭复用状态，保留错误诊断，loop 必须继续运行至完成。 |
| 错误 | 统一分类并保留后端标识和原始错误码，不借用临时诊断文本；首版不强制分配错误字符串。 |
| 完成时序 | 用户通知始终经指定 completion executor；不保证晚于发起函数返回，inline 或并发消费可能重入，调用前准备回调状态。 |

准备好读取结果是内部状态，不提前宣布成功；成功交付任务开始时与取消进行唯一终态裁决。
完成任务在执行前被拒绝或丢弃可进入失败；已经确定的终态不因后续观察者通知问题而再次改变。

共享请求例外需要明确：同 GUID 已有在途工作时，新调用加入其快照；快照承诺不意味着清除已有 cache 或证明资源内容版本一致。
资产摘要、修订复验、GPU 提交和场景事务继续由 Gneiss 管理。

## 核心验收

| 场景 | 必须观察 |
| --- | --- |
| 同 URI 同快照同步/异步解析 | 相同目标、路径与来源标记，无第二张权威挂载表 |
| 在途打开/读取时 unmount/remount/路由器销毁 | 旧对象保活，新请求用新快照，借用路径拒绝异步 |
| 嵌套挂载中途变化、循环 | 旧快照稳定，循环有明确失败，不无限递归 |
| 并发修改与快照获取 | 观察完整状态，无数据竞争；不在路由锁内运行用户后端/回调/析构 |
| 大文件小范围、溢出、EOF、增长/截断 | 预算与实际读量匹配，无 read_all 回退，无截断转换或伪完整结果 |
| 拒绝、提前/延迟完成、重复/丢弃凭证 | 一次终态、无永久 pending、结果完整回收 |
| 队列关闭、任务丢弃、分配失败 | 状态可查询，不切换线程兜底通知，不丢底层清理 |
| 多区间读取、取消/关闭竞争 | 区间互不干扰，句柄析构不等待，真实关闭发生在合法环境 |
| remount 后同 GUID 共享、reload | 沿用首次操作快照，缓存不自动替换，资产层可复验来源 |
| 来源和模块销毁 | 后端析构及回调清理先于模块 pin/allocator 失效 |

## 外部依赖与限制

不新增第三方依赖。CAORS 自有协议与模拟验收是必须出口；Gneiss 的 libuv 后端、CPU 资产到场景迁移由其仓库独立实施。
真实联合验证尚未执行，需可用宿主环境及适配提交恢复；不阻塞明确收窄的 CAORS 通用协议开发验收，
但阻塞“Gneiss/libuv 已接入”的声明，联合验证暴露契约缺陷时阻塞发布。
执行记录见 [v0.4.0 开发记录](../records/2026-10-19-v0.4.0-async-vfs.md)。
