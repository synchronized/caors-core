# 第三方依赖源码缓存迁移

## 状态与范围

实施中，目标为 [v0.6.0](../versions/v0.6.0.md)。参考 Granit 的依赖清单与 Gneiss 的按项文件锁，
在本仓库实现独立的 caors_ CMake 模块，不在构建时依赖相邻仓库。
保留 Catch2 3.15.0、ctrack 1.1.0 及现有 target 复用规则；迁移不夹带依赖升级。

## 设计与实施

依赖目录统一为 vendor；版本、上游提交、不可变归档 URL、SHA-256、入口文件及许可证集中维护。
缓存默认 vendor/cache，可显式指定其他目录；只共享只读源码，生成文件和对象文件仍按 build 隔离。
同名依赖按归档摘要加锁，持锁至下载、校验、解压、完成标记及重命名发布全部结束；
不同依赖不共用全局锁。等待有超时，函数返回或进程退出释放锁，不按锁文件是否存在判断占用。
使用唯一 staging；损坏归档和不完整 source 明确失败，不删除调用方已有目录。
已有源码只信任本协议的匹配完成记录与入口，不能仅看一个文件就接受旧的半成品。
缓存命中不进行联网；离线缺失直接失败。关闭测试/基准或复用合格父目标时不准备对应缓存。

## 边界

仅支持同一主机共享文件系统上遵守相同锁协议的配置进程；不承诺跨主机分布式锁。
手动修改完成缓存不受支持，恢复条件为使用新缓存目录或显式移走损坏项；不自动覆盖用户数据。
若与其他仓库共享物理缓存，需统一键、完成标记及锁协议；仅设置相同根目录不等于协议兼容。
