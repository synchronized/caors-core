# v0.6.0：依赖源码缓存与构建诊断治理

## 状态

2026-10-20 已发布 alpha 源码，最终验收与公开下载复核通过。
警告治理由 PR #47 集成；依赖迁移由 PR #48 集成，验收结果见关联记录。
工程版本已由 cmake/caors_version.cmake 调整为 0.6.0；最终 main SHA、制品及发布结果由[版本验收记录](../records/2026-10-20-v0.6.0-acceptance.md)维护。

## 固定范围与非目标

将测试 Catch2 3.15.0 和基准 ctrack 1.1.0 从仓库源码副本迁入按摘要锁定的 vendor/cache；
支持父项目目标复用、按需获取、离线命中、并发准备和失败诊断，并交付默认警告即错误的工程治理。
不升级第三方版本，不增加运行时依赖，不共享编译产物，不实现通用包管理器或自动发布系统。

## 关联任务与依赖

- [第三方依赖缓存迁移](../plans/dependency-source-cache.md)：身份、缓存、CMake 组装及验证。
- 警告治理已完成并合入 main，其验收见 PR #47；不重复运行没有变化的旧批次。

## 交付契约

源码与可安装 CMake 包，覆盖既有 Windows/Linux 常规矩阵；公共运行时 API 不因迁移改变。
测试或基准首次构建需要下载锁定源码，或由使用方提供兼容 target/预填缓存。
显式关闭测试与基准后，核心库及示例配置不获取这些开发依赖。源码归档不隐含包含忽略的缓存，离线测试必须显式预填。
缓存目录不进入 Git 或安装包；各编译器、配置及链接模式继续使用独立 build 目录。

## 发布门槛与证据

按[发布清单](../checklists/release-readiness.md)验收；迁移计划的冷缓存、离线、并发、损坏和父项目复用通过，
测试与两个基准目标可构建运行，跨平台及安装迁移通过。实际发布前仍须冻结最终 main SHA，
核对归档冷缓存获取与预填离线行为，不以开发分支结果冒充已发布。
固定 Linux 性能复验沿用 v0.5.0 已获准延期范围，不将缓存迁移声明为运行时性能改善。
