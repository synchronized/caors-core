# v0.3.0：异步 loader 与宿主 I/O 接入

## 状态

状态：规划中，alpha；尚未开始实现或验收，发布日期未定。
本页维护版本范围、依赖和出口；具体设计与任务由[异步 loader 计划](../plans/asynchronous-resource-loader.md)维护。
当前工程版本继续以 [caors_version.cmake](../../cmake/caors_version.cmake) 为准；规划不提前修改版本号，
也不代表 [v0.2.0](v0.2.0.md) 已公开发布。

## 固定范围与非目标

目标：让资源 loader 发起工作后立即返回，稍后交付资源所有权；上游可使用自己的 libuv 等异步 I/O 后端，
无需阻塞 CAORS worker 等待 I/O。接入 database 与 asset_manager，复用现有共享加载、独立订阅取消、
cache 提交和 coroutine 等待能力，同时保留同步 loader 的使用与适配路径。

本版交付加载与重载、同类型及跨类型依赖预加载、同步/异步混合注册、错误与取消收尾、
可安装公共接口、模拟宿主示例及接入指南。

不包含异步 saver、通用异步 stream/file_system 重构、内置 libuv 后端或其强制依赖、
GPU 上传、网络/远程资源协议、线程池背压/优先级、任务图、自动模块卸载保护或稳定 C++ ABI。
不承诺原生内核非阻塞 I/O、吞吐提升、确定尾延迟或完整无异常运行矩阵。

## 交付契约

交付源码与可安装 CMake 包；不交付预编译 SDK。宿主持有 I/O loop、backend、请求缓冲区与调度器，
CAORS 公共接口不暴露 `uv_*` 或其他第三方类型，也不创建或运行宿主 loop。
原同步 loader 与既有 request 返回类型保持可用；仅注册异步 loader 时同步入口的失败语义必须明确，
不能通过内部阻塞等待模拟同步支持。新增公共名字在实施前由 Plan 的接口评审收口。

平台与常规配置以[CI 策略](../guides/ci.md#常规矩阵)为准：Windows x64、Linux x86_64，
覆盖动态库两种编译器、代表性静态库与 sanitizer；Debug/其他组合按变更风险补充。
不扩大当前 ABI、异常或正式环境验证承诺；精确环境与实际结果在开发执行后写入 Record。

## 发布门槛

- 完成 Plan 四批实现与验收，覆盖回调提前完成、延迟完成、拒绝、丢弃、重复完成防护、取消竞争及关闭清理。
- 同步 loader 回归通过；异步 load/reload/preload、独立订阅与 coroutine 组合符合现有语义。
- cache 只在所属线程提交；取消后迟到的 I/O 回调仍正确释放结果和缓冲区，不访问已销毁服务。
- 按风险先专项验证，在完整集成批次运行 Linux 5 / Windows 3 常规 CI，安装/迁移 consumer 通过；
  不为每个中间提交重复启动全矩阵。最终发布遵循[发布清单](../checklists/release-readiness.md)。
- 无第三方依赖的模拟宿主是必需验收；上游 libuv 实际联合验证单独记录。
  缺少宿主环境时注明未验证范围，不宣称 libuv/Gneiss 已接入；联合验证发现契约缺陷时阻塞发布。
