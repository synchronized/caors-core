# v0.2.0：宿主集成与生命周期契约

## 状态

状态：实施中，alpha；维护入口为本版本页和关联 Plan。尚未实现全部范围、验收或发布，发布日期未定。
当前工程版本仍由 [caors_version.cmake](../../cmake/caors_version.cmake) 维护，发布准备前不提前修改。

位于其 `docs/plans/`；原检查基线为 CAORS `b46acead0b9aa568de10c936e7d40ac06b9ed2b6`。
CAORS 评审基线为 `ab6fe5c`；该提交的模块前缀与父工程探针只是已有基础，不代表整批需求已满足。
下表保留 C51 编号，后续交接不依赖本机绝对路径。

## 固定范围与非目标

目标：让宿主可以控制 CAORS 的链接方式、调度及卸载寿命，并为共享资源加载提供独立消费者取消。
按 2026-10-19 的范围调整，内置调度删除 Asio，改用标准库线程和队列，实施与验收见[标准库调度后端](../plans/standard-thread-backends.md)。
六项计划全部作为本版本出口；P0/P1/P2 表示实施顺序，不表示 P2 已默认延期。
如需缩减，必须显式修订本页、关联 Plan 和交接范围，不能把未完成项记为已验收。

不包含 Gneiss 的 GPU 上传、RID、场景事务、Prefab、撤销重做或插件系统；
不要求宿主改用 CAORS 线程池，不承诺跨编译器 C++ ABI、多版本对象混用或通用热卸载安全。
不将旧计划的固定环境性能复验、完整无异常运行矩阵或发布自动化并入本版。

## 交付契约

本版规划交付固定提交的源码及可安装 CMake 包，不承诺预编译 SDK；测试生成的安装包属于验收产物。
目标为 Windows x64 的 MSVC/Clang、Linux x86_64 的 GCC/Clang，静态/共享和 Debug/Release。
精确工具链、CRT、标准库、异常/RTTI 配置与依赖清单必须由最终 Record 固定；未测试组合不宣称支持。
macOS、其他架构、多版本 runtime 共存不在本版承诺范围。

共用 runtime 的 C++ 对象交换须满足[模块边界](../concepts/module-boundary.md)；
私有静态嵌入和独立 runtime 的数据交换边界由 C51-01 收口。
取消、构建选项或公开接口发生变化时，必须提供迁移说明并记录到 CHANGELOG，不能静默改变旧含义。

## 发布门槛

- 六项 Plan 各自完成实现、文档与验收，并附固定提交的 Record；现有测试结果不能替代新增验收。
- 完成[发布清单](../checklists/release-readiness.md)，特别是 Windows 矩阵、完整 Linux CI、
  ASan/UBSan、插件寿命和取消竞争压力测试，以及静态/共享安装与迁移 consumer。
- 完成三批集成回归：共享 runtime 身份与跨模块释放；强/弱引用及异步回调延迟卸载；
  宿主投递队列上的单次加载、独立取消与关闭终态。
- 最终 main SHA、版本元数据、生成版本、包版本及发布标签一致，按[发布流程](../guides/release.md)固定。
- Gneiss 联合验证作为接入证据独立记录；没有宿主环境时标为待验证，不宣称已经完成 Gneiss 接入。
  CAORS 自有模拟宿主验收仍为发布必需项；若发现联合验证揭示的契约缺陷，则阻塞发布。
