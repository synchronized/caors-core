# v0.5.0 VFS 后续能力开发记录

## 范围与状态

2026-10-20，用户确认 [v0.5.0](../versions/v0.5.0.md) 的推荐方案后开始实施。
当前为开发集成，工程版本仍为 0.4.0，未建立 v0.5.0 标签或 Release。
主集成评审入口为 [PR #44](https://github.com/synchronized/caors-core/pull/44)，当前保留草案。
三个议题的主实现已进入 feature/v0.5.0-vfs-followups；跨平台常规 CI 与 ASan 压力均已通过；
固定 Linux Release 性能复验仍未完成，不能称为版本已验收或已发布。

## 分支与实现批次

- 规划通过 [PR #40](https://github.com/synchronized/caors-core/pull/40) 合入 main。
- [PR #41](https://github.com/synchronized/caors-core/pull/41)，feature/resource-refresh：独立刷新与默认绑定保护、缓存插入/替换的分配失败回滚；已合入开发集成分支。
- [PR #42](https://github.com/synchronized/caors-core/pull/42)，feature/chunked-file-reading：串行聚合与同步逐块消费、迭代推进、预算/取消/通知处理、示例及安装 consumer；已合入开发集成分支。
- [PR #43](https://github.com/synchronized/caors-core/pull/43)，feature/provider-snapshot-cost：基准、同次 source 冻结共享、源码和真实模块回归；已合入开发集成分支。

当前 API 由 [资源参考](../reference/resources.md#显式刷新与默认绑定)和 [IO 参考](../reference/io.md#串行分块读取)
维护；Plan 只维护设计与待办，不将本记录的执行数据复制进计划正文。
刷新只处理根资源；依赖闭包发布、异步消费者确认和跨次快照缓存均未实现，范围与恢复条件见各 Plan。
结果构造/控制块分配先完成，随后才检查当前发布凭据并写入默认绑定；完成通知允许在更新结束后发起新请求。

## 本机正确性与安装

Windows 10 x64，Clang 23.1.1 / MSVC ABI / Shared Debug，构建目录 build/v030-clang-debug。
使用 scripts/msvc.ps1 加载 VS 环境，Ninja 并行度 2，未依赖普通 MSVC Ninja 的中文头依赖输出。

- 初轮全仓构建、公共头和 95/95 CTest 通过；原始/迁移前缀各 6/6 consumer 通过。
  日志 build/v050-integrated-build.log、v050-integrated-test.log、v050-integrated-package.log。
- IO、asset_manager、resources cache/manager/async/database、真实模块寿命七组各重复 25 次通过，
  包括 20000 个即时单字节块的非递归推进、双线程完成 executor、取消与通知丢弃。
  日志 build/v050-pressure-test.log；示例消费/聚合 100000 字节通过。
- source 共享优化与新的多 GUID 真实 DLL 场景加入后，全仓构建与 95/95 CTest、安装迁移各 6/6 再次通过。
  日志 build/v050-optimized-final-build.log、v050-optimized-final-test.log、v050-optimized-final-package.log。
- provider、asset_manager 与真实 DLL 寿命三组各重复 25 次通过，包含根刷新不触碰已缓存依赖，
  同次来源冻结计数、跨次 remount/rebind/unbind、失败与空根诊断、分配失败后旧快照可用。
  日志 build/v050-closure-test.log。逐块消费的加和摘要回归单独通过，日志 build/v050-checksum-test.log。
- 发布检查位置最后收口后，相关资源/模块六组专项全部通过，结果见 build/v050-publication-final-test.log。

分配故障注入仅覆盖显式 allocator 中大于 32 字节的申请，避免将 MSVC Debug 容器代理的 noexcept
小分配误报为可恢复异常；不宣称覆盖所有 STL/全局分配失败或完整无异常运行矩阵。
真实 DLL 测试同时覆盖 provider 同 source 的两个 GUID、unmount 后的在途打开、通知交付/丢弃、
逐块消费与显式关闭，最后文件/请求释放后才卸载模块。

## 性能证据

方法、环境、各轮数据及原始文件摘要唯一入口为
[Windows Clang 来源快照对比](../../benchmarks/results/2026-10-20-windows-clang-provider-snapshot.md)。
基线 d59cbb6e83698103594082d6dc30523ab1a25301，优化实现 602183206f2c28bd7b3fb294456a81f7ca5c8d78，
同机 Shared Release 前后各三轮，暖态各 31 样本、预热三次；原始 CSV 在 build/v050-measurements。
六份汇总已逐项与逐次样本重新计算核对，没有删除长尾样本。

仅采用同次捕获的 source 根共享，未实现跨次复用；GUID/路径仍全量复制。
不将 source 冻结调用次数减少当作已测得全局分配减少，也不宣称 Gneiss 卡顿根因或全面尾延迟改善。
