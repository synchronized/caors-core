## GCC 插件构建补充

新增的 GCC 共享库覆盖发现两个既有插件测试失败：类型冲突没有被诊断、模块未真实卸载；
该轮 asset_manager 的 45 个测试、809 条断言全部通过。
插件先前默认导出内部模板/静态状态，且 GCC GNU unique 符号可能阻止 dlclose 真实卸载。
现按插件契约隐藏内部符号，仅显式导出 ABI 入口，并为 Linux GCC 测试插件设置 -fno-gnu-unique；
未删除或放宽类型冲突、模块 pin、弱控制块与真实卸载断言。
宿主插件构建要求由[插件接入指南](../guides/plugin-integration.md#linux-插件符号与卸载)维护。


## 限制

示例和测试使用自有模拟 I/O，未执行真实 libuv 或 Gneiss 联合构建，不宣称已完成其接入。
loader、allocator、模块 pin、宿主 loop 与执行环境由宿主保证寿命，group 不延长 manager 的存活时间。
只承诺现有无异常头编译探针，尚非完整无异常运行验证；没有新后端吞吐或长期运行性能保证。


## 批次取消专项补充

完整批次检查发现，原预加载取消只影响聚合状态与缓存提交，未及时向等待宿主 I/O 的操作发送 stop。
现由批次持有各自订阅，在取消、失败或最后句柄释放时释放需求；其他批次及独立加载订阅仍保持隔离。
处理注册发布顺序，避免聚合取消与子订阅初始化竞争；已完成的订阅及时释放，避免批次无意延长资源 handle 寿命。
本地三组专项各重复 25 次通过，新增批次取消/放弃及失败时保留独立需求的回归。
初轮 CI 对应 d53d911，仅作阶段证据；最终 CI 必须覆盖本修复，不能以旧轮通过替代。

CMakeCXXCompiler.cmake 的中文 showIncludes 前缀已错误解码。该增量结果不能作为当前源码验收。
本机只安装 2052 诊断资源，VSLANG=1033 没有改变输出语言；未将无效设置留在包装脚本。
全新目录 build/v030-msvc-english 完整构建当前源码后，三组专项各重复 25 次通过，确认旧对象混用导致该轮崩溃。
该本机 Ninja 增量依赖问题尚未修复；只采用冷构建结果，后续头文件改动必须干净重建或使用 Visual Studio generator。
Clang 目录的 asset_manager.cpp.obj 实测头依赖为 340，正常跟踪本轮头文件改动。
