## 构建缓存排查与重新验收

Windows MSVC Release 初轮链接报告 layer_call_guard 重复定义，发现参与链接的 capability_test 对象
最后生成于 2026-08-05，Ninja 对该对象的头文件依赖记录为 0；本轮新对象的依赖记录为 192/381 等非零值。
因此清理八组 Windows 产物并重新构建，原增量结果仅作排查记录，不能作为最终 SHA 的完整验收。
MSVC 19.41.34123.0、Clang 23.1.1，目标均为 x64 / Windows MSVC ABI。

第三轮完整 Linux CI：[运行记录](https://github.com/synchronized/caors-core/actions/runs/39214048688)，
对应 `b176ec2`，正在验证 Asio 私有可见性修复及独立模块卸载。
后续 `47bf70c` 补上请求表查询的独立订阅边界与回归，最终验收必须覆盖该提交。

第三轮 Linux 完整矩阵最终 8/8 通过，包含 ASan/UBSan、符号审计、安装迁移与独立卸载用例。
此结果对应 `b176ec2`，不替代后续请求边界修复的最终验证。

新增确定性回归覆盖：最后订阅放弃与新登记窗口、晚订阅进度继承、终态回调释放自身请求句柄、
cache map 单次分配失败后全部订阅进入失败终态。最初持续拒绝分配的注入在 MSVC STL Debug
代理构造的 noexcept 路径触发 terminate/CRT 对话框，使用 LLDB 栈确认并停止该测试进程。
现改为单次节点分配失败，准确验证提交异常收尾；不把它作为持续耗尽内存仍可恢复的证明。

旧 Ninja 依赖日志还报告 premature end of file。最终候选使用全新构建目录，
避免残缺依赖记录和旧对象影响结论；已完成的本轮干净 MSVC Release 为 93/93，仍需最终源码增量/候选复核。
