## 首批验证

Windows x64，Clang 23.1.1 / MSVC ABI / Shared Debug，使用 build/v030-clang-debug。
当前目录已确认可追踪头依赖；采用 scripts/msvc.ps1 初始化 Visual Studio 环境后构建。

- caors_io_test 构建通过，IO 全组 CTest 各重复 25 次通过，涵盖原同步行为及两种路由器的拥有式挂载。
- 覆盖调用方释放所有权后继续读取、目标子路径、扩容与 erase、clear/析构、重复和空目标拒绝，以及模块凭据释放顺序。
- 控制块与负载分配故障注入后，旧路由保持、候选完整释放；此项不宣称覆盖所有 STL 内部分配失败。
- 两份公共头独立语法编译通过；原始及迁移安装前缀各 6/6 consumer 通过，基础 consumer 新增嵌套拥有式挂载，确认共享库导出可用。
- 日志为 build/v040-owned-build.log、build/v040-owned-test.log、build/v040-owned-package.log；代码已按 .clang-format 格式化。

首轮全分配点故障注入触发 MSVC Debug basic_string 的 noexcept 构造中小型容器代理分配，
进程进入 terminate，LLDB 证据在 build/v040-owned-debug.log。该路径属于现有 STL/allocator 约束；
本专项明确只对大于 32 字节的控制块和负载分配注入故障，其他尺寸不宣称已验证。
测试框架断言原先拦截了预期 bad_alloc，现先捕获待测调用，再在异常处理外验证结果。
修正测试后 IO 全组 25 轮通过，未放宽后端与 pin 的顺序断言。

本批未合入 main，不为中间提交启动完整矩阵；核心快照机制完成或完整集成批次合并前，
仍需按版本计划运行受影响平台 CI。

## 限制

功能验收通过；release/0.4.0 将工程版本设置为 0.4.0，最终版本提交和制品尚待发布验收。
真实 Gneiss/libuv 联合验证未执行：恢复条件为宿主适配和可运行 loop 环境；
不阻塞 CAORS 通用协议自身验收，但阻塞“Gneiss/libuv 已接入”声明，不能使用模拟结果替代。
手工拥有式挂载不得构造 shared_ptr 强引用环；循环诊断不自动拆除已有所有权环。
每个新操作复制 provider 全部 GUID 绑定，尚无大规模索引成本或正式吞吐承诺。
