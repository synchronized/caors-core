# 文档职责与唯一维护入口审查

## 范围与方法

- 日期：2026-10-19；整理基线：`7cce62d`，分支：`docs/documentation-standards`。
- 范围：自有 Markdown 的入口、目录、文件名、章节职责、状态与证据引用；第三方文档不改动。
- 方法：遍历目录与标题，核对入口图；重点比较稳定性、Beta、路线图、模块规划、构建、基准、
  Linux 验证、内存审计和插件边界的重复内容，并检查相关公共头与既有结果文件。
- 本次没有逐条核实所有 API 示例，没有重新运行历史测试或基准；结构检查不等同于 API 全量正确性验收。

## 发现与处理

| 问题 | 影响 | 本次处理 |
| --- | --- | --- |
| Beta 与 API 稳定性各维护候选、实验范围和 Gate | 协程、MessagePack 与完成队列说明已冲突 | 候选/实验范围统一到 API 政策；Gate 和扫描统一到 Beta 清单 |
| `api_stability.md` 是唯一下划线专题名，`beta.md` 实为执行清单 | 命名与职责不清 | 新规范路径为 `api-stability.md` 与 `checklists/beta-readiness.md`，旧路径仅保留迁移链接 |
| 路线图逐项列举 API 和数百条完成记录，模块参考另维护规划清单 | 维护多个进度来源，现状与未来混杂 | 路线图保留方向与依赖，模块参考链接路线图；旧清单完整归档 |
| Linux 执行清单内追加多轮历史验收 | 操作步骤与历史环境混杂 | 旧结果移入历史记录，清单保留步骤与记录模板 |
| 内存域审计放在 plans 中，实际为带日期/提交的基线 | 历史证据容易被当成实施状态 | 归位到 dated Record；旧路径保留导航，从计划分类移除 |
| Benchmark README 与指南各维护命令、用例和统计范围 | 路径和新用例容易失同步 | 指南为运行与用例维护入口，目录 README 只维护源码导航 |
| 性能结果目录只有记录规则，没有完整条目导航 | 多份结果只能靠目录或代码样式文件名检索 | 补齐历史测量 Markdown 索引，运行命令转向指南 |
| Registry 计划复制正式性能结果表 | 同一数字有两份维护位置 | 计划改为摘要链接，原结果表继续保留在 results |

| API 政策重复开发规范的公开边界规则，并含无日期扫描结论 | 规则与“当前验证通过”混淆 | 规则链接开发规范，扫描归清单，旧结论归档并标明证据不足 |
| DLL 指南与模块边界重复通用 runtime/ABI 前置条件 | native C++ 与独立稳定协议的边界不够清晰 | 通用规则统一到模块边界；DLL 指南保留接入、CRT、诊断和卸载用法 |
| 根 README 仍列出 completion queue，安装说明称三个 consumer | 当前说明已经落后于实现 | 根入口缩减为能力摘要，安装说明修正为四类 consumer 并链接结果入口 |
| 两份已完成计划仅以代码样式名称出现，缺少 Markdown 入链 | 从分类导航无法直接找到原设计 | 补齐 registry overlay 与 type identity state 的计划索引链接 |

不要求删除用户理解当前接口所必需的上下文，不允许把历史快照当作现行规则。

## 目录与文件名结论

- `docs/` 根目录的模块文档仍能按稳定主题检索，保留路径；本次不机械搬到 reference/guides。
- `checklists/` 适合维护可重复执行的检查步骤，`records/` 维护有提交/环境的结果，
  `records/history/` 保存旧快照，`plans/` 维护实施方案与待办；目录不再混淆这几类职责。
- `README.md` 用作目录入口；模块文件名以公开主题为准，例如 `object.md` 对应对象主题与聚合头，
  不因命名空间为 `objects` 就强制改名。`value.md` 对应 Meta 值体系，有明确索引语境，保留。
- 原下划线路径与移位清单保留短导航，文档中心使用新规范路径，不复制政策或 Gate 正文。
- 旧记录缺少执行日期时显式标注未知，文件名不伪造测试日期。

## 本次验证结果

- 遍历 90 份自有 Markdown，检查 246 个仓库内文件链接及标题锚点，未发现失效目标。
- docs 与 benchmarks 文档均有分类入链；三个有意保留的旧路径导航页不再进入现行目录索引。
- 本批 30 个修改/新增文件均为 Markdown，UTF-8、LF 和 SPDX/版权头检查通过。
- 原路线图和 Linux 历史段落的完整保留断言通过，已有性能测量文件未改动。
- `git diff --check` 通过；没有运行编译、CTest 或完整 CI，没有将 Beta 清单标为验收通过。

## 保留限制与后续检查

- Meta、属性、序列化和 Resources 的长篇参考仍按单主题保留；后续按“当前契约、组合指南、历史设计”
  的实际混合程度拆分，篇幅本身不作为改名或拆目录的依据。
- 既有已完成计划仍可能包含长篇设计背景和阶段记录；本轮保留设计依据，优先消除了当前入口的冲突，
  后续编辑对应主题时再逐段归档，不把历史目标改写成当前实现。
- 固定 Linux 性能、完整无异常运行矩阵等延期仍以对应计划为准；整理文档没有新增验证结果。
- 静态文件链接与标题锚点检查只能覆盖仓库内引用，不能证明外部链接、历史 CI 制品或代码示例可运行。
- 纯文档整理不触发完整 Linux CI；逐 API 核验和自动化文档门禁属于独立验证范围。
